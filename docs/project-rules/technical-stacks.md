## 3. 백엔드

### 가. 핵심 기술

| 기술 | 권장 버전 | 역할 |
| --- | --- | --- |
| Python | 3.12 이상 | 언어 |
| Django | 5.2 (LTS) | 웹 프레임워크 |

### 나. API 제공 방식

프론트엔드와 백엔드를 분리했으므로 HTTP 기반 인터페이스가 필요합니다. Django REST Framework 도입을 검토 중입니다. 확정 전까지 아래 원칙만 지킵니다.

1) 화면 렌더링과 데이터 제공을 섞지 않습니다.  
2) 응답 형식을 통일합니다.  
3) 직렬화 책임을 뷰에서 분리합니다.  

### 다. 인증·인가

| 구분 | 방식 | 비고 |
| --- | --- | --- |
| 로그인 | Google 계정 인증 | 연동 방식 검토 중 |
| 권한 | 회원 상태·역할 기반 | 미승인·활동회원·운영진 |
| 검증 위치 | 서버 | 화면 제어만으로는 불충분 |

### 라. 실행·의존성

1) 가상 환경을 사용합니다.  
2) 의존성은 파일로 고정합니다.  
3) 개발용과 운영용 설정을 분리합니다.

## 4. 데이터베이스

### 가. 주 데이터베이스

| 기술 | 권장 버전 | 역할 |
| --- | --- | --- |
| PostgreSQL | 16 이상 | 메인 RDB |

### 나. 마이그레이션

1) Django 마이그레이션으로 스키마를 관리합니다.  
2) 마이그레이션 파일을 저장소에 포함합니다.  
3) 수동으로 스키마를 바꾸지 않습니다.  

### 다. ORM 규칙

1) Django ORM을 사용합니다.  
가) QuerySet 우선 적용  
나) 복잡 집계: 집계 함수와 표현식  
다) 직접 SQL: 최후 수단  

2) N+1 문제 방지  
가) 정참조: `select_related`  
나) 역참조·다대다: `prefetch_related`  
다) 목록 조회 시 쿼리 수를 확인  

3) 조회 최적화  
가) 필요한 필드만 조회  
나) 자주 쓰는 조건은 인덱스 적용

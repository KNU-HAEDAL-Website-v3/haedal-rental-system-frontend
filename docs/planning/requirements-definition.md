# 1. 문서 개요

## 가. 작성 목적

이 문서는 해달 동아리 도서 관리 시스템의 요구사항을 확정합니다. 현재 동아리는 종이 대여 장부로 도서를 관리합니다. 이 방식은 재고 확인과 이력 추적에 한계가 있습니다. 본 문서는 수기 프로세스를 시스템으로 대체하기 위한 기준을 제시합니다.

문서의 독자는 개발자, 운영진, 검토자입니다. 개발자는 구현 범위를 확인합니다. 운영진은 업무 변화를 확인합니다.

## 나. 문서 범위

### 1) 포함 범위
가) 동아리방 도서의 대여와 반납  
나) 도서 등록과 목록 관리  
다) 회원 가입과 승인  
라) 반납 기한과 연체 관리  
마) 대여 이력 조회  

### 2) 제외 범위
가) 도서 외 물품 관리 (10장에서 향후 요구사항으로 개괄합니다.)  
나) 구현 기술 선정 (기술 스택은 미확정 상태입니다.)  
다) 화면 상세 설계  
라) 도서 구매와 예산 관리

# 2. 현행 업무 분석

## 가. 현행 대여 절차

동아리원은 다음 순서로 도서를 대여합니다.

1. 동아리방에 방문합니다.
2. 책꽂이 앞으로 이동합니다.
3. 필요한 도서를 찾습니다.
4. 도서가 있으면 대여 장부에 기입합니다. 기입 항목은 대여자명, 대여일, 대여 물품입니다.

## 나. 현행 반납 절차

동아리원은 다음 순서로 도서를 반납합니다.

1. 동아리방에 재방문합니다.
2. 기존 기입 줄에 반납일을 추가로 적습니다.
3. 도서를 책꽂이에 꽂습니다.
4. 동아리방을 나갑니다.

## 다. 보관 현황

책꽂이는 동아리방에 배치되어 있습니다. 도서는 맨 마지막 줄의 절반을 제외한 공간에 있습니다. 장서는 전공서와 자기계발서로 구성됩니다.

## 라. 문제점 분석

현행 방식의 핵심 문제는 정보의 단절입니다. 장부가 동아리방에만 있기 때문입니다. 상세 문제는 아래와 같습니다.

| 구분 | 문제점 | 영향 |
| --- | --- | --- |
| 사전 확인 | 방문 전에 재고를 알 수 없음 | 헛걸음 발생 |
| 기록 신뢰성 | 기입 누락과 오기입을 검증 불가 | 실물과 기록 불일치 |
| 기한 관리 | 반납 기한 개념 없음 | 장기 미반납 방치 |
| 추적 | 현재 대여자 파악에 시간 소요 | 회수 지연 |
| 보존 | 장부 분실·훼손 시 이력 소멸 | 복구 불가 |
| 활용 | 인기 도서와 이용률 집계 불가 | 구매 판단 근거 부재 |

# 3. 개선 방향

## 가. 개선 목표

시스템은 장부를 대체하되 절차는 늘리지 않습니다. 현행 절차의 편의성이 이용률을 유지하는 요소이기 때문입니다. 따라서 라벨 스캔으로 기입 단계를 대체합니다.

### 1) 세부 목표
가) 방문 전 재고 확인을 지원합니다.  
나) 대여 기록을 자동으로 남깁니다.  
다) 반납 기한을 자동으로 관리합니다.  
라) 이력을 영구 보존합니다.  

## 나. 개선 대여 절차

1. 웹에서 도서를 검색해 재고를 확인합니다.
2. 동아리방에 방문합니다.
3. 책꽂이에서 도서를 찾습니다.
4. 대여 화면에서 라벨을 스캔합니다.
5. 도서 정보를 확인하고 대여를 확정합니다.
6. 시스템이 반납예정일을 자동 부여합니다.

라벨 인식에 실패하면 제목이나 저자로 검색해 선택합니다.

## 다. 개선 반납 절차

1. 동아리방에 재방문합니다.
2. 반납 화면에서 라벨을 스캔합니다.
3. 시스템이 반납을 처리하고 결과를 표시합니다.
4. 도서를 책꽂이에 꽂습니다.

## 라. 절차 대응 비교

| 구분 | 현행 (As-Is) | 개선 (To-Be) | 비고 |
| --- | --- | --- | --- |
| 재고 확인 | 방문 후 육안 확인 | 방문 전 웹 조회 | 신규 |
| 대여 기록 | 장부 수기 기입 | 라벨 스캔 | 오기입 제거 |
| 대여자 식별 | 이름 자필 | 로그인 계정 | 신뢰성 확보 |
| 기한 관리 | 없음 | 자동 부여 | 신규 |
| 반납 기록 | 장부에 반납일 기입 | 라벨 스캔 | |
| 이력 보존 | 종이 보관 | 데이터 보관 | 분실 위험 제거 |
| 알림 | 없음 | 자동 발송 | 신규 |

## 마. 기대 효과

1) 헛걸음이 줄어듭니다.  
2) 실물과 기록이 일치합니다.  
3) 장기 미반납이 감소합니다.  
4) 이용 통계로 도서 구매를 판단합니다.

| 활동회원 | 운영진 승인을 받은 동아리원 | 대여·반납·연장 | 기본 사용자 |

## 나. 회원 상태 전이

회원은 아래 순서로 상태가 바뀝니다.

```
로그인 → 정보입력 → 승인대기 → 활동회원
                        ↓
                      반려
```

### 1) 전이 조건
가) 로그인: 외부 계정 인증을 완료합니다.  
나) 정보입력: 학번과 이름을 입력합니다.  
다) 승인대기: 운영진 판단을 기다립니다.  
라) 활동회원: 운영진이 승인합니다.  
마) 반려: 운영진이 사유와 함께 반려합니다.

# 5. 시스템 구성 개요

## 가. 운영 형태

시스템은 자체 서버에서 운영합니다. 동시에 외부 접속을 허용합니다. 회원이 동아리방 밖에서도 재고를 확인해야 하기 때문입니다.

## 나. 구성 요소

| 구분 | 역할 | 비고 |
| --- | --- | --- |
| 웹 클라이언트 | 사용자 화면 제공 | 스캔 기능 포함 |
| 서버 | 대여 규칙 처리 | 권한 검증 수행 |
| 데이터 저장소 | 도서·회원·이력 보관 | |
| 알림 발송 | 기한·연체 통지 | |

## 다. 지원 환경

### 1) 우선 환경
가) 모바일 웹을 우선 지원합니다.  
나) 현장에서 라벨을 스캔하기 때문입니다.  

### 2) 병행 환경
가) 데스크톱 웹을 함께 지원합니다.  
나) 운영진의 도서 등록 작업에 필요합니다.  

## 라. 구성 제약

1) 카메라 스캔에는 보안 연결이 필요합니다.  
2) 별도 앱 설치를 요구하지 않습니다.  
3) 구현 기술은 이 문서에서 정하지 않습니다.

# 6. 기능 요구사항

## 가. 요구사항 표기 규칙

### 1) 식별자 체계
가) 형식은 `FR-<영역>-<일련번호>` 입니다.  
나) 영역은 세 자리 영문 약어를 사용합니다.  

### 2) 우선순위 기준

| 구분 | 정의 | 비고 |
| --- | --- | --- |
| 필수 | 없으면 시스템이 성립하지 않음 | 1차 개발 대상 |
| 중요 | 운영 효율에 크게 기여함 | 1차 개발 권장 |
| 선택 | 있으면 좋은 기능 | 2차 이후 |

## 나. 회원·인증 (FR-MBR)

## 마. 품목 상태 전이

```
대여가능 → 대여중 → 반납완료 → 대여가능
              ↓
            연체 → 반납완료
              ↓
         분실 / 파손 → 폐기
```

### 1) 전이 규칙
가) 대여 시 상태를 대여중으로 바꿉니다.  
나) 반납예정일을 지나면 연체로 표시합니다.  
다) 반납하면 대여가능으로 되돌립니다.  
라) 분실과 파손은 운영진만 등록합니다.  

## 바. 데이터 보존 규칙

1) 대여이력은 삭제하지 않습니다.  
2) 도서를 폐기해도 이력은 남깁니다.  
3) 회원이 탈퇴해도 이력은 익명 처리해 남깁니다.

# 10. 향후 확장 요구사항

## 가. 확장 방향

동아리는 향후 전체 물품으로 관리 범위를 넓힐 계획입니다. 이번 범위에서는 도서만 다룹니다. 물품 종류와 수량이 확정되지 않았기 때문입니다.

## 나. 확장 수용 근거

7장의 데이터 모델이 확장을 수용합니다. 품목 공통 속성과 도서 전용 속성을 분리했기 때문입니다. 새 물품은 전용 속성만 추가하면 됩니다. 대여이력은 품목을 참조하므로 그대로 사용합니다.

## 다. 확장 시 추가 요구사항

| 구분 | 추가 요구사항 | 사유 |
| --- | --- | --- |
| 분류 | 물품 카테고리 체계 정의 | 도서 외 유형 구분 |
| 수량 | 동일 물품의 수량 관리 | 개별 라벨이 어려운 소모품 존재 |
| 상태 | 파손 정도와 수리 이력 관리 | 장비 특성 반영 |
| 절차 | 고가 물품의 반출 승인 | 관리 책임 강화 |
| 기간 | 물품별 대여 기간 차등 적용 | 도서와 장비의 특성 차이 |
| 보증 | 반납 확인 절차 강화 | 구성품 누락 방지 |

## 라. 확장 전 결정 필요 사항

1) 관리 대상 물품의 종류와 수량을 조사합니다.

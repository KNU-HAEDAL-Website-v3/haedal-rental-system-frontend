# 1. 프로젝트 개요

## 가. 프로젝트명

해달 동아리 도서 관리 시스템 구축

## 나. 추진 배경

동아리는 현재 종이 대여 장부로 도서를 관리하고 있다. 이 방식은 정보가 동아리방에만 머무는 구조이다. 그 결과 아래 문제가 반복된다.

1) 방문 전에 도서 보유와 대여 여부를 확인하지 못한다.
2) 기입 누락과 오기입을 검증할 방법이 없다.
3) 반납 기한 개념이 없어 장기 미반납을 추적하지 못한다.
4) 장부를 잃어버리면 이력이 통째로 사라진다.

## 다. 프로젝트 목적

이 프로젝트는 수기 대여 장부를 웹 시스템으로 대체한다. 동시에 향후 동아리 전체 물품 관리로 확장할 기반을 마련한다.

## 라. 기대 효과

| 구분 | 기대 효과 | 측정 방법 |
| --- | --- | --- |
| 이용 편의 | 방문 전 재고 확인으로 헛걸음이 감소 | 이용자 설문 |
| 기록 신뢰 | 실물과 기록 일치 | 정기 재고 점검 |
| 회수 | 장기 미반납 감소 | 연체 건수 추이 |
| 운영 | 도서 구매 판단 근거 확보 | 대여 통계 활용 |
| 확장 | 물품 관리로 확장할 기반을 갖춤 | 2차 착수 가능 여부 |

## 나. 배포 구성

회원 정보와 대여 이력은 동아리방 데스크탑에서 직접 관리한다. 화면은 외부 배포 서비스에 올린다. 두 곳이 분리되므로 외부에서 데스크탑에 접근할 경로가 필요하다.

### 1) 접근 경로 방식

데스크탑은 고정 주소가 없고 외부 인입이 막혀 있을 가능성이 높다. 따라서 데스크탑이 밖으로 연결을 거는 터널 방식을 적용한다.

| 구분 | 방식 | 필요 조건 | 채택 |
| --- | --- | --- | --- |
| 1안 | 터널 서비스 경유 | 도메인 1개, 데스크탑에 연결 도구 설치 | 채택 |
| 2안 | 공유기 포트 개방과 동적 주소 갱신 | 공유기 관리 권한, 인입 포트 허용 | 1안 불가 시 |
| 3안 | 서버와 데이터베이스를 외부로 이전 | - | 자체 관리 원칙과 충돌하므로 제외 |

터널 방식은 데이터를 외부로 옮기지 않는다. 통신 경로만 빌린다. 데이터는 동아리방 데스크탑에만 남는다.

### 2) 도메인 통합

프론트엔드와 백엔드를 같은 도메인 아래에 둔다.

| 구분 | 주소 | 연결 대상 |
| --- | --- | --- |
| 화면 | 도메인 최상위 | 외부 배포 서비스 |
| 데이터 | 도메인 하위 /api 경로 | 터널 경유 데스크탑 |

같은 도메인을 쓰면 교차 출처 설정과 인증 정보 전달 문제가 발생하지 않는다. 구현 기간을 줄일 수 있다.

### 3) 보안 연결

보안 연결은 선택 사항이 아니다. 아래 두 가지 이유로 필수다.

가) 외부 배포 화면은 보안 연결로 열리므로 비보안 서버를 호출하지 못함  
나) 카메라를 이용한 라벨 스캔이 보안 연결에서만 동작함  

인증서는 터널 서비스가 자동 발급하는 방식을 사용한다. 2안을 적용할 경우 무료 인증서를 발급받고 자동 갱신을 설정한다.

## 다. 데이터 보관과 백업

### 1) 보관 원칙
가) 회원 정보와 대여 이력은 동아리방 데스크탑에만 보관  
나) 외부 배포 서비스에는 화면 코드만 배치  
다) 개인정보는 학번, 이름, 이메일로 한정  

### 2) 백업 구성

백업을 원본과 같은 본체에만 두면 백업으로 기능하지 못한다. 디스크 고장, 도난, 실수로 인한 삭제가 원본과 백업에 동시에 미치기 때문이다. 따라서 보관 위치를 분리한다.

| 구분 | 보관 위치 | 주기 | 목적 |
| --- | --- | --- | --- |
| 1차 | 데스크탑 내 별도 디스크 또는 폴더 | 매일 자동 | 실수 복구 |
| 2차 | 외장 저장 장치, 동아리방 외부 보관 | 주 1회 | 본체 사고 대비 |
| 3차 | 운영진 개인 기기, 암호화 사본 | 월 1회 | 최후 수단 |

3차는 선택 사항이다. 다만 2차까지는 반드시 구성한다.

### 3) 백업 운영 규칙
가) 복원이 실제로 되는지 개시 전에 1회 시험  
나) 백업 파일은 암호화하여 보관  
다) 백업 담당자를 지정  

## 라. 데스크탑 운영 수칙

동아리방은 여러 사람이 드나드는 공간이다. 서버 보안보다 물리 접근이 먼저 문제가 될 수 있다.

1) 디스크 암호화를 적용한다.  
2) 자동 화면 잠금을 설정한다.  
3) 관리자 계정과 일반 사용 계정을 분리한다.  
4) 정전이나 재부팅 후 서버가 자동으로 시작하도록 설정한다.  
5) 방학 중 전원 유지 여부를 사전에 합의한다.  

## 마. 지원 환경

### 1) 우선 환경
가) 모바일 웹을 우선 지원
나) 현장에서 라벨을 스캔하기 때문

### 2) 병행 환경
가) 데스크톱 웹을 함께 지원
나) 운영진의 도서 등록 작업에 필요

## 바. 구성 제약

1) 카메라 스캔에는 보안 연결이 필요
2) 별도 앱 설치를 요구하지 않음
3) 자체 서버로 운영하되 외부 접속 허용
4) 데스크탑 전원이 꺼지면 서비스가 중단됨
